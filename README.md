# 可能性星云 · chess-cloud

下一步棋之后的所有可能未来，一次全画出来。

点开就能玩：你执白落一子，当前局面是标着「现在」的起点，之后每一层合法走法向未来方向张开成星。
星的颜色是那个未来的评估分：**暖色=白方占优，冷色=黑方占优，中性灰=均势**。
黑方由一个自写的 minimax + alpha-beta 引擎在 Web Worker 里应手。

**在线玩**：https://maxi-max-dev.github.io/chess-cloud/

## 星云里到底有多少颗星

以起始局面为例，四层全展开：

| 层 | 含义 | 星数 |
|---|---|---|
| 0 | 当前局面自己 | 1 |
| 1 | 白方所有走法 | 20 |
| 2 | 再加黑方所有应手 | 400 |
| 3 | 第三步 | 8,902 |
| 4 | 第四步 | 197,281 |

这些不是估算，也不是写死在页面里的数字：页面把每一层的星数从 three.js 几何体的
`position.count` 现读出来，`verify.mjs` 在 Node 里独立递归数一遍全树，两边必须一个不差。
第 4 层的 197,281 颗是公认的 perft(4) 标准值。

## 怎么跑起来的

- 第 1～4 层全部在专用 Web Worker 里展开；主线程只把 Worker 返回的真实数组做成
  Three.js geometry，不再同步枚举棋局。
- 第 4 层（起始局面 197,281 颗）按父节点分批送回，边算边长。手机上星图在屏外时只铺到
  第 3 层，进入视口后才完整续长第 4 层；离开视口会释放最重的第 4 层，回来再从真实第 3 层
  完整重建，不会拿截断结果冒充全量。
- AI 用迭代加深搜索，桌面思考预算 1.5 秒、手机/矮视口 0.9 秒，时间到就交上一层搜完的最好走法，
  主线程另有 2.2 秒 watchdog：Worker 超时或失败就走预存的合法保底步。重开会直接终止旧搜索，
  新请求不会排在旧任务后面。黑方思考期间不计算注定会被应手替换的中间星云；AI 落子先完成绘制，
  再在后续任务重建分叉和最终星云。新分叉就绪前，旧分叉会保持淡化并设为 `inert`，不能被鼠标、
  触摸或键盘误选。
- 评估函数（子力 + 位置表）全项目只有一份，在 `engine.js` 里。
  星的颜色和 AI 眼里的好坏读的是同一个函数——不然画面和棋力就是两个世界。

## 可能性分叉（主视图）

右边整块是主舞台，一列就是一步棋：

- 列头直接写着这一步**一共有多少种走法**（`你有 20 种走法` / `他有 20 种走法`），
  这个数字和 `count(该局面, 1)` 是对撞过的。
- 列里先摆**最靠谱的几条**，其余折成「展开其余 N 条」；展开后同一个入口会变成「收起」。
- 排序不是只看眼前一步，是**往前看两步**：「我走这步，对手挑他最好的回应之后，局面值多少」。
  只看一步的话，送后和吃兵长得一样好，排出来的「最靠谱」是假的。
- 亮蓝主干贯穿五列，表示当前选中的整条路径。点任意一条，右边几列立刻顺它重新分叉；
  选到推荐区之外的走法时，列表会自动收起但保留那张已选卡。触屏会显示详情并在棋盘预览，鼠标停留也会预览，
  底下告诉你这步之后对方有多少种回应、它在这一列里排第几。

左上角是**全景星图**的小窗：根点标着「现在」，所有未来从这里向右长出。点开全屏后会显示
真实 SAN 走法标签和当前前三步的亮线；拖动视角时近处标签显现、远处标签和星点淡出。
点第一层标签只会同步选择路径，不会直接落子。

分叉图也是防作弊的：卡片数从 SVG 里真数 `<g class="card">`，每列声明的总数拿
`count(该列局面, 1)` 去撞，排序方向也验（第一名对行棋方不能比第二名差）。

手机竖屏按「棋盘 → 分叉 → 星云」纵向排列；分叉在自己的面板里横滑，不会把整页撑宽。
短横屏和平板改成棋盘/星云在左、分叉在右。星云全屏使用动态视口和安全区，旋转屏幕也不会露底。

棋盘的六种棋子都是本地分层 SVG 几何：黑白双方共用造型，只切换象牙/炭黑材质、高光和侧面阴影。
页面不再使用系统 Unicode 棋子字体，因此不会因 Safari、彩色字体或字体回退把白棋渲染成黑棋。
这里的“3D”指确定性的分层矢量立体造型，不是可旋转、可自由换相机的 WebGL mesh 棋盘。

## 文件

- `index.html` — 页面：统一 3D 矢量棋子与棋盘、three.js 星云、分叉和视角控制
- `engine.js` — 唯一的评估函数 + minimax 搜索 + 逐层展开
- `worker.js` — Web Worker：AI 应手 / 第 1～4 层星云，页面各开一个实例
- `verify.mjs` — Node 端验收：递归数全树，和 perft 标准值对撞
- `live-check.mjs` — 无头 Chrome 验收：真实星数/路径、棋子/FEN、黑白真实像素、触摸、AI 时限
- `HANDOFF.md` — **交接文档**：架构、红线、踩过的坑、实测基线、下一步候选
- `BLOCKED.md` — 待裁决清单（19 条）

不用打包、不用构建、没有后端。chess.js 和 three.js 直接从 CDN 引。

```bash
node verify.mjs                                      # 棋核验收（需先 npm i chess.js@1.4.0）
node live-check.mjs                                   # 无头 Chrome 真机验收（本地起服务器）
node live-check.mjs --url https://maxi-max-dev.github.io/chess-cloud/   # 打线上
```

`live-check.mjs` 用 `EXPECTED_RESULTS = 64` 锁住固定 64 项，少跑一项也会失败。最近一次反向验证在
当时的 63 项版本上同时故意破坏关键路径，验收准确出现 **10/63 项失败**；恢复后才继续扩到 64 项。
最终又让黑象只剩公共底座并仅在手机端删掉星云第 2 层，固定套件准确出现 **6/64 项失败**；
恢复正式实现后完整复跑为 64/64。

## 已知边界

- 兵到底线默认升变成后，没做选棋子的界面。
- 搜索只判将死和困毙，不判三次重复 / 50 步 / 子力不足和棋，残局会略微自我感觉良好。
- 星云的第 4 层直接对子局面做静态评估，「子局面正好是困毙」这种极少数情况会被当成普通局面上色。
- 星图目前可直接选择第一步并展示前三步主路径；从任意深层星点“穿越”进去继续下仍是下一期。
