# 落子教练与可能性路径网 · chess-cloud

点一枚棋子先看“我怎么走、对手优先怎么回”，再把下一步之后的所有未来一次全画出来。

点开就能玩：你执白。点白棋后，黄线动画预演你的候选，蓝线接着预演黑方的强回应；
它不会偷偷落子。评价先说“接近均衡 / 你稍优 / 风险较高”，原始加减分只作核对。

当前局面是标着「现在」的起点，之后每一层合法走法向未来方向张开成真实父子路径线。
线的颜色来自那个未来的评估：**暖色=白方占优，冷色=黑方占优，中性灰=均势**。
黑方由一个自写的 minimax + alpha-beta 引擎在 Web Worker 里应手。

**在线玩**：https://maxi-max-dev.github.io/chess-cloud/

## 路径网里到底有多少条未来

以起始局面为例，四层全展开：

| 层 | 含义 | 路径数 |
|---|---|---|
| 0 | 当前局面自己 | 1 |
| 1 | 白方所有走法 | 20 |
| 2 | 再加黑方所有应手 | 400 |
| 3 | 第三步 | 8,902 |
| 4 | 第四步 | 197,281 |

这些不是估算，也不是写死在页面里的数字：每个未来节点恰有一条真实入边，零 `THREE.Points`；
页面从非索引 `LineSegments` 的 `position.count / 2` 现读路径数，`verify.mjs` 在 Node 里独立递归
数一遍全树，两边必须一个不差。第 4 层的 197,281 条是公认的 perft(4) 标准值。

## 怎么跑起来的

- 第 1～4 层全部在专用 Web Worker 里展开；主线程只把 Worker 返回的真实数组做成
  Three.js geometry，不再同步枚举棋局。
- 缩略窗只铺到真实第 3 层；只有明确点「放大探索」才从保存的第 3 层继续算第 4 层。第 4 层
  按父节点分批送回，完成后合并成一个尺寸刚好的真实 geometry；收起立刻释放最重的第 4 层，
  再次放大时完整重建，不会拿截断结果冒充全量。
- WebGL 改成事件驱动：默认不巡航，只有拖动、缩放、数据到达或短暂镜头过渡时画帧，静置后
  `requestAnimationFrame` 与 WebGL 新帧都归零。缩略窗固定 DPR 1；全屏桌面最高 1.5，手机最高 1.25。
- AI 用迭代加深搜索，桌面思考预算 1.3 秒、手机/矮视口 0.9 秒，时间到就交上一层搜完的最好走法，
  主线程另有 2.2 秒 watchdog：Worker 超时或失败就走预存的合法保底步。重开会直接终止旧搜索，
  新请求不会排在旧任务后面。黑方思考期间不计算注定会被应手替换的中间路径网；AI 落子先完成绘制，
  再在后续任务重建分叉和最终路径网。新分叉就绪前，旧分叉会保持淡化并设为 `inert`，不能被鼠标、
  触摸或键盘误选。
- 评估函数（子力 + 位置表）全项目只有一份，在 `engine.js` 里。
  路径颜色、候选人话和 AI 眼里的好坏读的是同一个函数——不然画面和棋力就是两个世界。

## 棋子助手

- 候选来自当前局面的 `rankMoves(..., {depth:2})`，只过滤到你点的那枚棋子，最多先展示前三条。
- 每条候选再从落子后局面调用 `rankMoves(..., {depth:1})`，列出黑方前三条强回应并明确标注：
  这是引擎强度排序，不是历史胜率。
- 点击候选只换动画，不改 FEN；“就走这步”才会真正落子。AI 实际回应后会说明是否命中预演；
  fallback 会展示真实原因，不把故障伪装成预测成功。
- 默认升变双方统一为后；一步将死会直接结束助手状态；棋盘格支持触摸、鼠标和键盘。

## 可能性分叉（主视图）

右边整块是主舞台，一列就是一步棋：

- 列头直接写着这一步**一共有多少种走法**（`你有 20 种走法` / `他有 20 种走法`），
  这个数字和 `count(该局面, 1)` 是对撞过的。
- 列里先摆**最靠谱的几条**，其余折成「展开其余 N 条」；展开后同一个入口会变成「收起」。
- 排序不是只看眼前一步，是**往前看两步**：「我走这步，对手挑他最好的回应之后，局面值多少」。
  只看一步的话，送后和吃兵长得一样好，排出来的「最靠谱」是假的。
- 亮蓝主干贯穿五列，表示当前选中的整条路径。点任意一条，右边几列立刻顺它重新分叉；
  选到推荐区之外的走法时，列表会自动收起但保留那张已选卡。触屏会显示详情并在棋盘预览，鼠标停留也会预览，
  底下告诉你这步之后对方有多少种回应、它在这一列里排第几。

左上角是**全景路径网**的小窗：根路径终点标着「现在」，所有未来从这里向右长出。点「放大探索」后，
线图旁会同时出现一块真实 3D 矢量棋盘和当前局面的全部合法走法。点线旁标签或右侧走法，都能连续
预演最多三步；棋盘逐格显示“如果当时改走这一步，局面会变成什么”，面包屑可退回任一步，
而真实对局完全不动。拖动旋转，`＋/－` 缩放，“回到全景”恢复视角；近处标签显现，远处标签随雾隐藏。

同一位置现在可点「切到 2D 树」：从「现在」开始，每层横排当前父局面的**全部合法走法**，
每张卡直接写“走后 N 个分支”；选中一条就向下长出下一层，亮蓝主干连续连到所选节点。
缩略图也保留当前层的真实分叉数；全屏可用左右箭头、横滑和纵向滚动浏览，右侧变体棋盘与这条路径
始终是同一串 `after` FEN。2D 模式不会加载 L4、不会重画隐藏 WebGL，也不会在放大时给隐藏画布扩容。

分叉图也是防作弊的：卡片数从 SVG 里真数 `<g class="card">`，每列声明的总数拿
`count(该列局面, 1)` 去撞，排序方向也验（第一名对行棋方不能比第二名差）。

手机竖屏按「棋盘 → 分叉 → 路径网」纵向排列；分叉在自己的面板里横滑，不会把整页撑宽。
短横屏和平板改成棋盘/路径网在左、分叉在右；667×375 的全屏探索也有专门双栏布局。
2D 树在手机全屏位于上方、变体棋盘位于下方，支持真实横滑、纵滑和三层触摸选路。
路径网全屏使用动态视口和四边安全区，旋转屏幕不会露底，所有关键入口均按至少 44px 触控目标验收。

棋盘的六种棋子都是本地分层 SVG 几何：黑白双方共用造型，只切换象牙/炭黑材质、高光和侧面阴影。
页面不再使用系统 Unicode 棋子字体，因此不会因 Safari、彩色字体或字体回退把白棋渲染成黑棋。
这里的“3D”指确定性的分层矢量立体造型，不是可旋转、可自由换相机的 WebGL mesh 棋盘。

## 文件

- `index.html` — 页面：统一 3D 矢量棋子、棋子助手、3D/2D 路径网、分叉和视角控制
- `engine.js` — 唯一的评估函数 + minimax 搜索 + 逐层展开
- `worker.js` — Web Worker：AI 应手 / 第 1～4 层路径，页面各开一个实例
- `verify.mjs` — Node 端验收：递归数全树，和 perft 标准值对撞
- `live-check.mjs` — 无头 Chrome 验收：真实路径数、助手、棋子/FEN、真实像素、触摸、AI 时限
- `HANDOFF.md` — **交接文档**：架构、红线、踩过的坑、实测基线、下一步候选
- `BLOCKED.md` — 待裁决清单（19 条）

不用打包、不用构建、没有后端。chess.js 和 three.js 直接从 CDN 引。

```bash
node verify.mjs                                      # 棋核验收（需先 npm i chess.js@1.4.0）
node live-check.mjs                                   # 无头 Chrome 真机验收（本地起服务器）
node live-check.mjs --url https://maxi-max-dev.github.io/chess-cloud/   # 打线上
```

`live-check.mjs` 用 `EXPECTED_RESULTS = 82` 锁住固定 82 项，少跑一项也会失败。2D 新验收会从
DOM 现读每层节点、分叉徽章和连续 SVG 主干，再由 Node 独立重放每一步。反向验证曾故意把所有
“走后 N 个分支”报大 1，新增裁判立即逐节点报红；恢复真实值后才完整复跑 82/82。

## 已知边界

- 兵到底线默认升变成后，没做选棋子的界面。
- 搜索只判将死和困毙，不判三次重复 / 50 步 / 子力不足和棋，残局会略微自我感觉良好。
- 路径网第 4 层直接对子局面做静态评估，「子局面正好是困毙」这种极少数情况会被当成普通局面上色。
- 全屏探索目前可交互预演三步；从第四层或更深的任意节点继续穿越仍是下一期。
